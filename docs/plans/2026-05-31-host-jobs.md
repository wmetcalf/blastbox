## The generic `Job` (base.py)

Generalize ClippyShot's `Job` — drop engine-specific fields (`pages_done`/`pages_total`,
`scan_options`, `detected`) and replace with generic carriers:

```python
class JobStatus(str, enum.Enum):
    QUEUED = "queued"; RUNNING = "running"; DONE = "done"
    FAILED = "failed"; EXPIRED = "expired"

@dataclass
class Job:
    job_id: str                 # uuid4
    engine: str                 # which engine handles this job
    filename: str               # sanitized input basename
    status: JobStatus
    created_at: float
    started_at: float | None = None
    finished_at: float | None = None
    expires_at: float | None = None
    input_sha256: str | None = None
    result_dir: str | None = None        # server-set; stripped from public dict
    worker_runtime: str | None = None
    error: str | None = None
    security_warnings: list[str] = field(default_factory=list)
    params: dict[str, str] = field(default_factory=dict)        # engine per-job options (was scan_options)
    result_summary: dict | None = None   # small engine result summary for listing (was pages/detected)

    @classmethod
    def new(cls, *, engine: str, filename: str) -> "Job": ...   # uuid4 + QUEUED + created_at=time.time()
    def to_dict / from_dict / to_public_dict  # to_public_dict strips result_dir + params, sanitizes error
```

`JobStore` protocol is unchanged from the reference: `create / get / update / list / claim_next / delete`.

## Deltas / requirements (the parts review will check hardest)

1. **SQLite `claim_next` = status-guarded CAS** (carry this session's fix): the `UPDATE` must include
   `... AND status = 'queued'` and check `rowcount == 1`, returning `None` (don't claim) on 0. Keep
   `BEGIN IMMEDIATE` + the instance lock. Postgres `claim_next` = `FOR UPDATE SKIP LOCKED` +
   `UPDATE ... RETURNING` (already correct in the reference).
2. **SQL fully parameterized** — every value bound via the driver paramstyle (`?`/`%s`), never
   f-string-interpolated. `update()` validates field names against a `_COLUMNS` allowlist before
   building the SET clause. Table/column names are constants only.
3. **Redis** — JSON serialization (NOT pickle), `scan_iter` (NOT `KEYS`), a TTL on every `set`, and an
   atomic claim via `WATCH`/`MULTI`/`EXEC` with `WatchError` retry. Key = `<prefix> + job_id`.
4. **Retention** — `shutil.rmtree` confined to `result_dir`'s parent resolved under a job-root base
   (re-check containment before deleting); no shell; gate non-`{DONE,FAILED,EXPIRED}` jobs out of
   expiry. Don't follow symlinks blindly; log rather than `ignore_errors=True`-swallow.
5. **`Limits`** (generalize, keep the bounds I added): generic resource + output-trust caps only —
   `timeout_s`, `memory_bytes`, `tmpfs_bytes`, `max_input_bytes`, `max_metadata_bytes`,
   `max_artifact_bytes`, `max_total_artifact_bytes`, `max_artifacts`. All bounds-checked in
   `__post_init__` (1 ≤ x ≤ sane ceiling); `from_env()` reads `BLASTBOX_*` and fails loudly with the
   offending var name on bad input. NO engine-specific limits (dpi/max_pages/width/height belong to engines).
6. **`errors`** — generalize the hierarchy: `BlastboxError` base + `DetectionError`, `SandboxError`
   (+`SandboxTimeout`,`SandboxUnavailable`), `EngineError`, `ConversionError`/`DetonationError`,
   `ValidationError`-style. Carry the **root-agnostic** `sanitize_public_error` (the
   `/(?:[A-Za-z0-9._+-]+/)+...` absolute-path matcher I switched to this session — NOT the old root denylist).
7. No `clippyshot`/engine names anywhere; everything is `blastbox`/engine-agnostic.

2. **limits.py** — generic caps + bounds + loud `from_env`. Tests: defaults valid; `=0`/negative/huge

3. **jobs/base.py** — generic `Job` + `JobStore`. Tests: `new()` shape; `to_public_dict` strips
   `result_dir`+`params` and sanitizes `error`; `to_dict`/`from_dict` round-trip incl. `params`/`result_summary`.
4. **jobs/memory.py** — `InMemoryJobStore` (threading.RLock). Tests: CRUD; `claim_next` returns oldest
   QUEUED and flips to RUNNING atomically; concurrent claims (threads) never double-claim one job.
5. **jobs/sql_store.py** — sqlite + postgres (postgres path testable via `psycopg` only if a DSN is set;
   otherwise gate those tests). Tests (sqlite): CRUD; `update()` rejects a non-allowlisted field;
   `claim_next` is a status-guarded CAS — a job flipped to EXPIRED between select and update is NOT
   clobbered to RUNNING (assert via monkeypatched/forced interleaving or a direct CAS unit test);
   parameterization (a `filename` containing `'); DROP` round-trips intact).
6. **jobs/redis_store.py** — `RedisJobStore` over `fakeredis`. Tests: CRUD via JSON; TTL set on create;
   `claim_next` atomic under two concurrent claimers (WatchError retry); `list` uses scan.
7. **jobs/retention.py** — sweeper. Tests: expires only terminal-status jobs past `expires_at`;
   `rmtree` confined to job-root (a `result_dir` pointing outside the base is refused); a symlinked
   escape inside the result dir is not followed out of the base.
